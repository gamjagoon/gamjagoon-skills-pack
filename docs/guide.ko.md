# 한국어 사용 안내

이 도구는 제한 시간 개발을 위한 Codex 워크플로와 프로젝트 로컬 역할을 설치합니다. 기본 설치는 외부 스킬을 다운로드하지 않습니다.

## 설치하고 실제 작업 시작하기

작업 폴더에서 Codex에 **“gamjagoon-skills-pack 설치해줘”**라고 요청하세요. 설치 에이전트는 공개 저장소의 [설치 안내](../INSTALL.md)를 따라 현재 폴더에 구성하고 설치된 지침을 같은 대화에서 읽습니다. 사용자가 명령을 외울 필요는 없습니다. 설치 자체는 제작 시계를 시작하지 않습니다.

직접 CLI를 사용할 때는 다음 명령으로 미리 보고 설치합니다.

```sh
gsp setup . --dry-run
gsp setup .
```

`PATH`를 생략하면 현재 폴더를 사용합니다. `setup`은 워크플로·역할·Enter 줄바꿈을 구성하고 설치 파일을 검사합니다. `--minutes` 기본값은 180분입니다. 명시된 사용자 시간 예산과 기존 `TASK.md`가 우선합니다. 설치 시 실제 시작·마감은 미정으로 남고, 실제 제작 작업을 받은 에이전트가 clock 도구나 시스템 시계로 기록합니다. 재개해도 기존 시작과 마감을 초기화하지 않습니다. 단순 질문에는 180분 제작 절차를 적용하지 않습니다.

기존 `AGENTS.md` 본문과 `TASK.md`를 보존합니다. 관리 파일이 충돌하면 사전 확인 후 중단합니다. 검토 후 `gsp init . --overwrite`를 명시하면 교체 대상의 백업을 만들고 갱신합니다. `--dry-run`은 파일이나 새 폴더를 만들지 않습니다. 설치 기록과 백업은 프로젝트의 `.gamjagoon-skills-pack/`에 보관됩니다.

## 기본 180분 진행

설치 후 같은 대화에 실제 작업 지시를 전달하세요. 에이전트는 원문 요구사항과 완료 기준부터 정리하고 구현·검증·인계까지 이어갑니다. 단계마다 사용자가 프롬프트를 입력하거나 재승인할 필요는 없습니다. 필수 결정이 빠졌거나 승인 범위를 바꿔야 할 때만 근거와 권고를 제시합니다.

| 경과 시간 | 결과 |
| --- | --- |
| 0–20분 | 요구사항, 완료 기준, 최소 설계 |
| 20–130분 | 구현과 작은 확인, 60분까지 핵심 흐름 실행 |
| 130–165분 | 검증, 독립 리뷰 1회, 중요한 결함 수정 |
| 165–180분 | 최종 재실행, 실행법과 남은 한계 인계 |

다른 예산은 구간을 비례 조정합니다. 핵심 흐름 실행이 지연되면 필수 요구사항을 보존하며 부가 범위를 줄입니다. 빨리 끝나면 예산까지 기다리지 않습니다. `TASK.md`에 원문 근거, 검증 방법, 결정, 설계, 실행 결과와 미실행 한계를 유지합니다.

`gsp prompt`는 선택적으로 지시를 확인하는 도구입니다. `start`, `requirements`, `requirements-review`, `design-tasks`, `plan-review`, `feasibility`, `implement`, `implementation-review`, `verify`, `handoff` 중 필요한 이름을 `gsp prompt STAGE`로 볼 수 있습니다. 열 이름은 열 번의 수동 승인 단계가 아닙니다. 계획의 추가 독립 리뷰도 기본 요구사항이 아닙니다.

## 역할과 병렬 작업

메인 모델은 Sol / medium을 권장하지만 현재 실행 모델이나 전역 설정을 바꾸지 않습니다. 사용자가 명시한 모델이 우선입니다.

| 설치 역할 | 모델 / 추론 | 범위 |
| --- | --- | --- |
| `gsp-triage` | Luna / low | 읽기 전용 로그·사실 추출 |
| `gsp-researcher` | Luna / medium | 읽기 전용 탐색·일차 출처 조사 |
| `gsp-worker` | Luna / medium | 격리된 지정 범위의 구현·실험 |
| `gsp-integrator` | Sol / medium | 복잡한 구현·통합 |
| `gsp-debugger` | Sol / high | 위험하거나 모호한 디버깅 |
| `gsp-reviewer` | Sol / medium | 읽기 전용 독립 리뷰 |

필요한 독립 작업만 나누고 고정 병렬 수를 두지 않습니다. [병렬 작업 안내](parallel-work.md)에는 실행 가능한 worktree·경로별 patch·허용 목록 복사 예시가 있습니다. 읽기 전용 작업은 공유 저장소를 사용할 수 있고, 쓰기 실험은 별도 디렉터리를 사용합니다. dirty baseline은 현재 변경을 검토해 명시적으로 전달합니다. worktree는 보안 경계가 아니므로 cwd·출력·환경·포트도 직접 확인합니다. 부모만 결과를 통합하고 최종 검증합니다.

역할·모델·기능이 없으면 한계를 밝힙니다. 현재 허용 모델로 대체할 수 있다는 기존 사용자 선호가 있을 때만 그 범위에서 대체하고, 없으면 필요한 선택만 묻습니다. 그 선택과 무관한 작업은 계속합니다. 독립 리뷰를 실행하지 못했다면 미실행으로 기록하고 자체 점검을 독립 리뷰라고 표시하지 않습니다. 설치 및 `doctor` 성공은 실제 역할·모델 호출 성공을 뜻하지 않습니다.

## 선택 스킬과 문제 해결

```sh
gsp skills list
gsp skills add NAME --path . --dry-run
gsp skills add NAME --path .
```

사용자가 선택한 외부 스킬만 명시적으로 다운로드합니다. 목록의 출처·고정 커밋·라이선스와 스킬의 지침·의존성을 검토하세요. 기존 스킬은 덮어쓰지 않습니다. 기본 워크플로에는 외부 스킬 추가가 필요하지 않습니다. `init`, `prompt`, `doctor`는 네트워크 없이 사용할 수 있습니다.

충돌이 나면 `--dry-run`과 대상 파일을 먼저 확인하고 의도한 관리 파일만 갱신합니다. 실제 검증은 작업 성격에 맞게 수행합니다. 정적 검사·테스트·모의 실행·실제 Codex 실행·사용자 환경 실행은 각각 다른 근거이며, 실행하지 않은 항목은 성공으로 표시하지 않습니다. 이 도구는 Codex를 자동 실행하거나 자동 push·배포하지 않습니다.
