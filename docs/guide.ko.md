# 한국어 사용 안내

이 도구는 제한 시간 개발을 위한 원본 Codex 워크플로와 프롬프트를 프로젝트에 설치합니다. 특정 대회의 공식 도구나 규칙을 대변하지 않습니다. 기본 설치는 외부 스킬을 다운로드하지 않습니다.

## 처음 사용하기

새 작업 폴더에서 Codex를 켜고 **“gamjagoon-skills-pack 설치해줘”**라고 요청하세요.
설치 에이전트는 공개 저장소의 [설치 안내](../INSTALL.md)를 따라 현재 폴더에 구성하고,
설치된 지침을 현재 대화에서 읽습니다. 사용자는 명령을 외우거나 직접 실행하지 않아도 됩니다.

직접 CLI를 사용하는 경우에만 아래 명령을 참고하세요.

```sh
gsp setup . --dry-run
gsp setup .
```

`PATH`를 생략하면 현재 폴더를 사용합니다. 통합 `setup`은 워크플로·리뷰어·Enter 줄바꿈을 구성하고 설치 파일을 검사합니다. `--minutes`는 질의응답과 제출 시간을 제외한 실제 제작 시간 예산이며 setup의 기본값은 180분입니다. 개별 `init`은 기존대로 240분입니다. 시작과 마감 시각은 확인하기 전까지 미정입니다. 설치 검사는 Codex 에이전트를 실제로 실행하지 않습니다.

기존 `AGENTS.md` 본문과 `TASK.md`를 보존합니다. 관리 파일이 다른 내용과 충돌하면 사전 확인 후 중단합니다. 내용을 검토한 뒤 `gsp init . --overwrite`를 명시하면 교체 대상의 백업을 만들고 갱신합니다. `--dry-run`은 파일이나 새 폴더를 만들지 않습니다. 설치 기록과 백업은 프로젝트의 `.gamjagoon-skills-pack/`에 보관됩니다.

## 단계별 사용

설치 후 같은 Codex 대화에 원문 작업 지시를 전달하고 요구사항부터 시작하도록 요청하세요.
Codex가 설치된 스킬과 현재 단계의 참조 문서를 읽고 `TASK.md`에 결과를 유지합니다.
직접 프롬프트를 확인하고 싶을 때는 `gsp prompt`로 목록을 보고 `gsp prompt STAGE`로 출력할 수 있습니다.

| 단계 | 사용할 때 |
| --- | --- |
| `start` | 목표와 실제 제작 시간, 기존 상태를 확인할 때 |
| `requirements` | 원문의 필수 항목과 각각의 완료 기준을 정리할 때 |
| `requirements-review` | 사람이 범위와 중요한 미결정을 검토할 때 |
| `design-tasks` | 간단한 설계와 실행 가능한 작업을 만들 때 |
| `plan-review` | 요구사항부터 작업 순서까지 통합 계획을 독립 검토할 때 |
| `feasibility` | 위험한 의존성을 작은 실험으로 확인할 때 |
| `implement` | 핵심 흐름부터 점진적으로 구현할 때 |
| `implementation-review` | 변경과 실행 근거를 읽기 전용으로 검토하고 결함을 수정할 때 |
| `verify` | 완료 기준에 따라 실제 확인 결과를 기록할 때 |
| `handoff` | 사용자가 직접 실행하고 남은 한계를 인계받을 때 |

순서는 작업에 맞게 반복할 수 있습니다. `TASK.md`에는 모든 필수 요구사항의 원문 근거와 검증 방법, 결정, 설계, 작업, 관찰 결과와 미해결 한계를 기록합니다. 사람은 범위와 중요한 미결정을 판단하고, 이미 승인된 작업은 반복 확인 없이 계속할 수 있습니다.

## 리뷰 전달

지원되는 Codex 환경에서는 설치된 읽기 전용 `gsp-reviewer`를 활용할 수 있습니다. 지원되지 않으면 별도 리뷰 대화에 원문 작업 지시, 최신 `TASK.md`, 현재 변경 파일, 실제 실행·검증 근거와 해당 리뷰 프롬프트를 함께 전달하세요. 발견에는 출처와 위치, 발생 조건 또는 재현 방법, 영향을 요청하고 확인하지 못한 사항은 따로 기록합니다. 설치 및 `doctor` 성공은 실제 리뷰어 호출 성공을 뜻하지 않습니다.

## 선택 스킬과 문제 해결

```sh
gsp skills list
gsp skills add NAME --path . --dry-run
gsp skills add NAME --path .
```

선택한 외부 스킬만 명시적으로 다운로드합니다. 목록의 출처, 고정 커밋, 라이선스를 확인하고 스킬 자체의 지침과 의존성을 사용 전에 검토하세요. 기존 스킬은 덮어쓰지 않습니다. 기본 `init`, `prompt`, `doctor`는 네트워크가 필요하지 않습니다.

충돌이 나면 `--dry-run` 결과와 대상 파일을 먼저 확인하세요. 프로젝트 자료를 보존한 상태에서 의도한 관리 파일만 `--overwrite`로 갱신할 수 있습니다. Codex가 리뷰어를 지원하지 않거나 찾지 못하면 별도 읽기 전용 리뷰 대화를 사용하세요. 정적 검사, 테스트, 모의 실행, 실제 Codex 실행 및 사용자 환경 실행은 각각 다른 근거이며 실행하지 않은 항목은 성공으로 표시하지 않습니다.

이 도구는 Codex를 자동 실행하거나 모델 설정을 변경하지 않으며, 자동으로 push 또는 배포하지 않습니다.
