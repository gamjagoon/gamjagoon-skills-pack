# gamjagoon-skills-pack

**요구사항 작성부터 개발·리뷰까지 이어가는 Codex 작업 환경입니다.**

`AGENTS.md`가 작업 순서를 안내하고, **스킬 4개와 리뷰 에이전트 1개**가 역할을 나눕니다.
요구사항·아키텍처·개발은 각각의 스킬로 진행하며, 세 단계의 리뷰는 하나의 `gsp-reviewer`가 담당합니다.
모호한 결정은 `gsp-grilling`을 통해 사용자에게 질문합니다.

`AGENTS.md`, 스킬, 에이전트 지침은 영어로 작성되어 있습니다. 이 README는 한국어로 사용법을 설명합니다.

## 설치와 업데이트

작업할 폴더에서 Codex를 켜고 다음과 같이 요청하세요.

> gamjagoon-skills-pack 설치해줘.

이미 설치했다면 다음과 같이 요청하세요.

> gamjagoon-skills-pack 업데이트해줘.

Codex가 저장소의 `install.sh`를 읽고 현재 프로젝트에 적용합니다. 설치 명령을 외울 필요가 없으며,
Python·uv·npm 패키지도 필요하지 않습니다. 설치 스크립트는 Linux/WSL의 Bash와 기본 Unix 도구를 사용합니다.

이름으로 저장소를 찾지 못하면 [저장소 주소](https://github.com/gamjagoon/gamjagoon-skills-pack)를 함께 전달하세요.
새 스킬이나 에이전트가 보이지 않으면 Codex에서 프로젝트의 신뢰 상태를 확인하고 다시 실행하세요.
설치 스크립트는 전역 설정을 수정하거나 프로젝트를 자동으로 신뢰 처리하지 않습니다.

## 작업 맡기기

설치한 뒤에는 만들거나 고칠 내용을 요청하면 됩니다. 단계별 스킬을 따로 호출할 필요는 없습니다.

> CSV 파일을 읽고 항목별 합계를 출력하는 CLI를 만들어줘. 잘못된 입력 처리와 테스트도 포함해줘.

기본 흐름은 다음과 같습니다.

| 순서 | 단계 | 담당 |
| --- | --- | --- |
| 1 | 요구사항 작성 | `gsp-requirements` 스킬 |
| 2 | 요구사항 리뷰 | `gsp-reviewer` · `requirements` 모드 |
| 3 | 아키텍처 작성 | `gsp-architecture` 스킬 |
| 4 | 아키텍처 리뷰 | `gsp-reviewer` · `architecture` 모드 |
| 5 | 개발·검증 | `gsp-development` 스킬 |
| 6 | 개발 리뷰·수정 확인 | `gsp-reviewer` · `development` 모드 |

특정 단계만 맡길 수도 있습니다.

> 요구사항만 작성해줘.

> 현재 설계를 아키텍처 관점에서 리뷰해줘.

이 경우 요청한 범위에서 마칩니다. 작은 수정은 필요한 단계만 적용합니다.
기존 작업 문서가 있으면 이어 사용하고, 없으면 실제 개발 중 `TASK.md`에 요구사항·설계·검증 결과를 모읍니다.
설치만 요청했을 때는 개발 작업을 시작하지 않습니다.

## 검토용 문서 받기

요구사항·설계·개발·리뷰 결과는 **Markdown과 HTML 두 형식**으로 남기도록 지시합니다.
별도의 출력 형식 프롬프트 없이, 기본적으로 `TASK.md`와 `TASK.html`을 만들고 두 파일의 링크를 전달합니다.
기존 문서 위치나 사용자가 지정한 형식이 있으면 이를 우선하며, 단순 질문이나 설치만 할 때는 문서를 만들지 않습니다.
문서는 사용자가 요청한 언어로 작성합니다.

| 문서 | 검토 방법 |
| --- | --- |
| Markdown | 요구사항 ID, 결정 근거, 변경 이력과 검증 결과를 읽고 수정하는 원본 기록 |
| HTML | 브라우저에서 목차·상태 요약·표를 보며 검토하는 보기용 문서 |

문서 앞부분에는 현재 단계, 이전 버전에서 달라진 점, 막힌 사항과 사용자 결정이 필요한 질문을 모읍니다.
본문에는 요구사항·완료 기준, 설계 선택과 대안, 리뷰 지적과 수정 상태, 실제 검증 결과와 미실행 항목을 정리합니다.
리뷰 에이전트는 검토 결과를 반환하고, 주 작업자가 Markdown을 갱신한 뒤 같은 내용으로 HTML을 맞춥니다.

HTML은 CSS를 포함한 단일 파일로 작성하며, 서버·별도 빌드·외부 라이브러리 없이 로컬에서 열 수 있도록 합니다.
긴 코드와 로그는 접어서 볼 수 있게 하고 인쇄용 스타일도 제공합니다. 요청한 단계 밖의 결과를 채워 넣거나,
검증하지 않은 내용을 완료로 표시하지 않습니다. 파일 쓰기가 금지된 요청에서는 대화에 Markdown으로 반환하고 HTML 미생성을 알립니다.

## 스킬과 에이전트의 역할

| 구성 | 역할 |
| --- | --- |
| [AGENTS.md](AGENTS.md) | 작업 순서, 리뷰 진행 조건, 모델 활용과 병렬 작업의 공통 지침 |
| [gsp-requirements](.agents/skills/gsp-requirements/SKILL.md) | 원문에 근거한 범위·요구사항·완료 기준 작성 |
| [gsp-architecture](.agents/skills/gsp-architecture/SKILL.md) | 구조·인터페이스·구현 작업·검증 방법 설계 |
| [gsp-development](.agents/skills/gsp-development/SKILL.md) | 구현, 실제 실행, 기존 기능의 회귀 검증 |
| [gsp-grilling](.agents/skills/gsp-grilling/SKILL.md) | 모든 단계에서 모호한 사용자 결정을 질문으로 확인 |
| [gsp-reviewer](.codex/agents/gsp-reviewer.toml) | 요구사항·설계·구현을 각 모드의 기준으로 독립 검토 |

### 모호한 내용은 질문합니다

결과를 바꾸는 의도·정책·기대 동작이 불명확하면 선택지와 추천안을 함께 묻습니다.
파일이나 실행으로 알 수 있는 사실은 먼저 조사하고, 이미 답한 내용은 재사용합니다.
답변에 의존하는 부분은 기다리며, 답변과 무관한 작업은 계속합니다.
리뷰 에이전트가 발견한 질문도 주 작업자가 모아서 전달합니다.

### 리뷰는 에이전트 하나가 담당합니다

리뷰 에이전트 정의는 `gsp-reviewer.toml` 하나입니다. 가능하면 같은 리뷰 대화를 이어 사용하면서
검토 모드와 현재 원문·산출물을 새로 전달합니다. 리뷰어는 검토 결과를 반환하고,
주 작업자가 수정과 다음 단계 진행을 담당합니다.

| 판정 | 후속 행동 |
| --- | --- |
| PASS | 검토 범위에 차단 사항이 없고 근거가 있으면 다음 단계로 진행 |
| WARN | 비차단 제안·한계를 기록하고 진행 |
| FAIL | 해당 문제에 의존하는 작업과 완료 판정을 보류하고 해결 근거 확인 |

수정한 결함은 원래 실패 조건으로 다시 확인합니다. 최종 결과에는 실제 검증 내용과 미실행 항목을 남깁니다.
리뷰마다 사용자 승인을 반복해서 요구하지 않으며, 결과를 바꾸는 미결정만 질문합니다.

### 모델과 병렬 작업

리뷰 에이전트는 **GPT-6.1 Sol / medium**으로 설정됩니다. 다른 작업의 Sol/Luna 역할별 권장값은
[AGENTS.md](AGENTS.md)에 있습니다. 주 작업 모델·전역 설정·서비스 속도는 자동으로 변경하지 않습니다.
에이전트는 [공식 Codex 형식](https://learn.chatgpt.com/docs/agent-configuration/subagents)을 사용하며,
별도의 `config.toml`은 설치하지 않습니다.

읽기 전용 조사는 원본을 공유할 수 있습니다. 파일을 바꾸는 실험과 검증은 worktree나 임시 폴더로 분리하고,
환경·출력·포트와 담당 파일을 구분합니다. 명령 예시와 통합 절차는
[병렬 작업 안내](.agents/skills/gsp-development/references/parallel-work.md)에 있습니다.
리뷰어의 읽기 전용 지침은 별도의 보안 경계가 아니며, 실제 권한은 부모에게서 상속합니다.

## 설치되는 파일

```text
AGENTS.md
.codex/agents/
└── gsp-reviewer.toml
.agents/skills/
├── gsp-requirements/SKILL.md
├── gsp-architecture/SKILL.md
├── gsp-development/
│   ├── SKILL.md
│   └── references/parallel-work.md
└── gsp-grilling/SKILL.md
```

기존 `AGENTS.md`에서는 팩이 관리하는 블록만 갱신합니다. 다른 사용자 지침·스킬·에이전트,
`.codex/config.toml`, `TASK.md`, 입력 키 설정은 보존합니다.
같은 내용은 다시 쓰지 않으며, 교체하는 기존 파일은 `.gsp-backups/`에 백업합니다.
이 백업 폴더를 제외하는 규칙도 프로젝트의 `.gitignore`에 추가합니다.

구버전의 세 리뷰 스킬은 업데이트 시 차이를 확인한 뒤 백업·제거하고 단일 리뷰 에이전트로 전환합니다.
같은 폴더의 다른 파일은 보존합니다. 더 오래된 팩의 `timeboxed-workflow`나 별도 역할 TOML은
스크립트가 자동 삭제하지 않으며, 출처를 확인한 뒤 이전 팩의 파일만 백업해 정리합니다.
현재 구성인 `gsp-reviewer.toml`은 정리 대상이 아닙니다.

사용자가 설치나 업데이트를 요청하면 **이 저장소의 `install.sh`를 사용하세요.**
개별 스킬용 설치 도구나 수동 복사로 대신하지 않습니다.

1. 사용자의 원래 프로젝트 절대 경로를 기록한다. 저장소의 현재 `main`을 임시 소스 경로에 내려받고 README와 `install.sh`를 읽는다. `AGENTS.md`, `.agents/skills/`, `.codex/agents/gsp-reviewer.toml`을 모두 포함한다.
2. 원래 프로젝트를 명시해 미리보기를 실행하고, 성공하면 실제 설치한다.

   ```bash
   bash "$source_dir/install.sh" --dry-run "$project_dir"
   bash "$source_dir/install.sh" "$project_dir"
   ```

3. 관리 파일이 다르거나 구버전 리뷰 스킬이 남아 있으면 기본 설치는 중단된다. 차이를 검토해 사용자 수정을 보존·병합한다. 교체·정리가 적절하면 `--overwrite --dry-run`으로 확인한 뒤 `--overwrite`로 백업·적용한다. 설치를 통과시키기 위해 사용자 내용을 버리지 않는다.
4. `.agents`나 `.codex` 쓰기에 승인이 필요하면 정상 승인 절차를 이용한다. 승인이 불가능하면 미완료와 차단 원인을 알린다. 권한을 우회하지 않는다.
5. 설치된 `AGENTS.md`, 스킬 4개, 참조 문서와 리뷰 에이전트 정의를 읽는다. 파일 설치 성공과 네이티브 에이전트 로드는 구분한다. 역할이 로드되지 않으면 한계를 알리고, 지침에 따라 대체 독립 리뷰 또는 자체 점검 여부를 명시한다. 작업 요청이 없으면 설치 완료 후 기다린다.

스크립트는 다운로드나 모델 호출을 하지 않습니다. 대상 폴더를 생략하면 현재 폴더를 사용합니다.
사용자 홈·전역 Codex 설정 경로와 관리 대상 심볼릭 링크는 거부합니다.
실패 시 복구를 시도하며, 동시에 변경된 파일과 백업은 보존합니다.
