## 원문과 범위

> DAG를 명시적으로 만들고 python 스크립트를 돌려서 최적화 라우팅을 하는거 추가해줘 해당 스크립트의 역할이 의존성 검사, 포맷검사 등이 포함이야

앞선 사용자 맥락은 Task를 의존관계에 따라 병렬 처리해 완료 시간을 줄이려는 것이다. 현재 프로젝트의 [Task 스킬](../../.agents/skills/gsp-tasks/SKILL.md), [병렬 작업 규칙](../../.agents/skills/gsp-development/references/parallel-work.md), Markdown 전용 문서와 명시적 installer 목록을 유지한다. 새 도구는 작업 배정 제안을 계산하고, 기존 주 작업자가 격리·권한·통합 책임을 유지한다.

이번 완료 목표는 설치 가능한 동작 도구와 사용 지침·검증 결과다. 자동 agent 실행기, 모델 라우터, 전역 설정 변경, 전체 일정의 수학적 최적해 증명, 원격 배포는 포함하지 않는다. 입력 정보만으로 알 수 없는 실제 작업 시간·미신고 파일 충돌·완료 증거의 진실성은 확인했다고 주장하지 않는다.

## 검증 경계

Python은 작성된 DAG의 구조와 선언된 제약을 검사한다. Markdown 설명의 의미나 실제 코드 의존성을 자동으로 완전히 추론하지 않는다. 리뷰어가 코드·설계·Task와 DAG의 일치를 확인한다. 병렬 한도는 실제 사용 가능한 agent·예산·자원에 맞게 주 작업자가 명시하며 임의 기본값을 두지 않는다.

별도 탐색 PoC는 필요하지 않다. 기존 CLI·installer 구조를 활용해 구현하고 합성 그래프와 설치 fixture로 검증한다. 최적화는 결정적인 휴리스틱이며 일반 최적해나 수치 속도 목표는 요구하지 않는다.
