- 현재 단계: 작은 기존 지침 변경의 구현·검증 완료. 독립 development 리뷰 PASS.
- 범위: 요청한 작업보다 GSP 전체 절차를 우선하는 연결 문구 수정. 기존 네 리뷰 모드와 검증·DAG·협업 도구는 유지.
- 기준: `a54c5f53527248c83b21bfd9db9c9b33fd0061b7`, 시작 작업 트리 clean. 별도 deadline 없음.
- 결과: 호출 조건과 단계 연결 수정 및 로컬 회귀 검증 완료. 실제 새 Codex 행동 재현은 미실행.
- 사용자 결정 대기: 없음. “빠르게 수정하고 commit 하고 push 해줘”로 앞선 수정안 실행과 게시 승인.

## 요청과 수용 기준

사용자 사례: 기존 요구사항이 있는 상태에서 다른 Codex에 “front 디자인 먼저”를 맡겼으나, 요구사항 정리 → 리뷰 → 아키텍처를 다시 시작했다. 사용자는 “무조건 강제 하지 말자는거임”이라고 정정했다. 이후 기존 기능을 유지하고 범위 우선 규칙 및 충돌하는 연결 문구만 수정하는 안을 실행하도록 요청했다.

| ID | 수용 기준 | 확인 방법 |
| --- | --- | --- |
| RS-R1 | 사용자가 지정한 범위·순서를 기본 단계 순서보다 우선한다. | AGENTS와 네 생산 스킬의 적용 범위·handoff 확인 |
| RS-R2 | 기존 세션 산출물을 재사용하고 문서·리뷰 누락만으로 앞뒤 단계를 자동 시작하지 않는다. | 새 세션·누락·실제 차단 조건 문구 확인 |
| RS-R3 | UI·화면·시각 디자인을 시스템 아키텍처 요청으로 자동 해석하지 않는다. | AGENTS, architecture description 및 README 사례 확인 |
| RS-R4 | 전체 GSP 요청의 네 리뷰와 DAG·검증·소유권·인터페이스 제약을 유지한다. | 기준 diff, 리뷰어 계약과 기존 설치·도구 회귀 확인 |
| RS-R5 | 변경을 검증하고 commit/push하며, 지침 검증과 실제 모델 행동 증거를 구분한다. | 실행 결과·독립 리뷰·원격 SHA 확인 |

## 변경과 적용 범위

- C-SCOPE-1: [AGENTS](../AGENTS.md#requested-scope-and-order)에 범위 우선 규칙을 추가했다. “그 단계까지”를 “해당 범위만”으로 바꾸고 문서 생성·리뷰·후속 진행을 실제 수행 범위에 연결했다.
- [요구사항](../.agents/skills/gsp-requirements/SKILL.md), [아키텍처](../.agents/skills/gsp-architecture/SKILL.md), [개발](../.agents/skills/gsp-development/SKILL.md)의 호출 설명과 네 생산 스킬의 시작 경계를 맞췄다. [작업 계획](../.agents/skills/gsp-tasks/SKILL.md)의 DAG 계약은 변경하지 않았다.
- [리뷰어](../.codex/agents/gsp-reviewer.toml)의 공통 입력 경계가 부분 작업에 불필요한 전체 단계 문서를 요구하지 않도록 명시했다. 실제 필수 정보·검증 부족은 계속 차단한다.
- [README](../README.md#작업-맡기기)에 전체 진행의 적용 조건과 다섯 사례를 추가했다.
- 요구사항 작성법·아키텍처 방법·네 리뷰 모드·도구 구현·모델 설정은 유지했다. 다른 프로젝트 설치나 전역 설정 변경은 범위 밖이다.
- 앞선 사용자 합의와 기존 산출물을 재사용하는 작은 지침 변경이므로 별도 요구사항·아키텍처·작업계획 단계 및 새 DAG를 생성하지 않았다. PoC는 불필요하다. 검증 문서는 본 파일 하나이며, 공유 세션 기록은 Git 밖에서 유지한다.

## 독립 리뷰

- 모드: development, RS-R1–RS-R5와 변경 지침 범위. 원문은 위 사용자 사례와 수용 기준.
- 방법: native `gsp-reviewer` 역할을 `gpt-6.1-sol` / high로 실행하고 로컬 단일 계약을 제공했다. 원본 수정·쓰기 검사 없이 development 범위를 독립 검토했다.
- 기준: 위 HEAD와 현재 변경. AGENTS, README, 네 생산 스킬, reviewer TOML, 본 문서의 여덟 SHA-256이 검토 시작·종료에 모두 일치했고 HEAD·Git 변경 목록도 유지됐다.
- 직접 읽은 자료: 위 여덟 산출물, grilling·change-management 계약, 저자의 세션 기록과 해시·정적 결과·unittest 로그, 관련 기존 완료 세션 기록.
- 판정: **PASS**. RS-R1–RS-R4 차단 결함 없음. RS-R5의 증거 구분 적절. 게시와 원격 SHA 확인은 리드가 수행한다.
- 리뷰어 직접 확인: `git diff --check`, TOML 파싱, 격리 사본과 현재 지침 일곱 파일의 byte 동일성, README 다섯 사례와 기존 단계 입력·handoff 문구의 의미 일관성.
- 저자 증거를 읽어 확인: unittest 60개 통과와 정적 검사. 독립 테스트 재실행은 수행하지 않았다.

| 없음 | 없음 | RS-R1–RS-R5 | 확인된 결함·미결정 사용자 질문 없음 | 수정 요구 없음 |

실제 새 모델 세션 행동과 브라우저·시각 검사는 NOT_RUN이다. 이는 현재 지침 수정 범위의 차단 사유로 판정되지 않았다. 리뷰 결과만 기록하는 후속 문서 변경은 저자가 재확인하며 지침 baseline은 유지한다.

## 전달

- 게시 대상: 사용자 승인된 현재 원격 `origin`의 `main`. 실제 commit ID와 push 후 원격 SHA 대조 결과는 최종 전달 메시지와 로컬 세션 기록에 남긴다.
- 게시 전 관리 블록 밖 사용자 지침 및 기타 skill·참조·도구 파일의 byte 보존을 확인했고, credential-pattern 검사에 검출 사항이 없었다. 설치·도구 구현과 모델 설정은 변경하지 않았다.
- 다른 프로젝트에 설치된 사본은 자동 업데이트하지 않는다.
